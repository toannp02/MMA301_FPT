# Placed-style studio: implemented scope and remaining parity

The user requested the full product direction of Placed, beyond the example video. This iteration implements a substantial photo-studio workflow. It is not full Placed parity and does not reconstruct a 3D room from a photograph.

## Current workflow

Interiors -> Add your room -> Take a Photo / Choose from Photos -> local wall suggestion -> Artworks (Discover / My artworks) -> View on room -> automatically apply to the active room -> adjust -> Save / export PNG. If no room is active, a single saved room is used automatically; multiple rooms show a picker. Selecting art edits a copy and never overwrites a saved design until Save. Saved opens rooms containing artwork. The earlier live camera preview and native Android AR remain secondary routes.

The shared editor runs in the SDK57 native package and isolated SDK58 iPhone Expo Go companion. Expo Go imports no Viro and cannot provide anchored AR or LiDAR capture.

Implemented:

- Additional style/zoom pass: shadow direction/softness, visual Bare/Slim/Classic/Float/Canvas edge presets, direct artwork width/height with proportional lock, fine plus/minus controls, separate room viewport zoom/pan and artwork pinch resize. See STYLE_ZOOM.md for precise scope and physical testing limits. View zoom does not crop exported PNG or alter saved dimensions.

- Local reusable wall spaces, up to20, including durable copies of the room and each selected artwork. Deleting an imported artwork does not remove its independently saved wall snapshot. Originals are never modified.
- Four draggable convex wall corners and homography perspective; user-entered wall width/height in cm. Approximate defaults remain visibly labelled until manually calibrated.
- Bounded local photo assistance: a 96px JPEG is decoded without Node Buffer, smooth light-colour regions suggest an empty rectangle and mild image tone. A low-resolution colour mask can preserve foreground outside the matching wall region. This heuristic can mistake furniture or miss walls; it is not semantic segmentation, measured dimensions, depth or 3D. Users can correct corners, disable Occlusion, or replace the suggestion with manual painting. Failed analysis falls back to manual placement. No room-photo upload is used.
- Active-room memory, automatic initial art fit, gold selection/dimensions, tap-to-position and four proportional resize handles. Eight visual layout presets and Style sections Frame / Image / Light, image reset/room-tone match, shadow intensity/offset and Occlusion toggle. Preview and PNG share appearance and mask settings.
- Own artwork/library/camera import, title and physical width, preserved image proportions. Imported images are bounded to2048px/1MB; existing collection limit10 remains explicit.
- Matching normalized-image SHA256 fingerprints warn about exact duplicates. Users can use an existing artwork or explicitly import another copy. This is not perceptual similarity detection, and older imports without fingerprints are not silently reprocessed.
- Swipe on art to browse, thumbnail collection switching, close inspection, dragging, proportional scale and rotation. Oversized pieces are fitted within the wall; inspect shows effective dimensions.
- One to nine artwork slots, pair, stack, row, column and grid presets, automatic fitting/centering and requested maximum gap. Each slot can receive a different artwork. Frames/mounts retain physical thickness during fitting.
- No frame / black / white / wood-colour face, mount, manual shadow strength, simple glazing highlight, brightness, contrast, saturation, hue and warmth. These are photo-rendering controls; no lighting sensor claim or volumetric frame/canvas depth.
- Manual foreground painting restores the photographed lamp/plant/furniture over the art; brush size, undo and clear. Mask strokes and optional photo-assisted colour masks are saved and exported. No automatic depth/semantic segmentation claim.
- Text, orientation, maximum physical width and existing category filters, in collection and editor. Search works on real local metadata.
- Original illustrated living-room, bedroom and gallery examples generated by scripts/generate-sample-rooms.py. These are labelled illustrations, not the user's private footage or photographs scraped from another product.
- Original/design comparison, editable save, PNG export without editing handles/controls. Native uses view-shot and the OS share sheet; browser downloads a raster PNG with embedded images and an image-load timeout.
- Navigation removal guard and browser reload guard for dirty designs; explicit discard. Controls pause while saving/exporting. Recoverable errors and image reload are provided.

## Data, implementation and failure handling

Domain: src/domain/spaces.ts; geometry/layout/rendering/discovery/editor state in src/features/studio. UI: SpacesScreen, SpaceEditorScreen and src/ui/studio. Assets/export/filesystem live in src/infra; repositories remain outside UI/domain and expose Result contracts. No direct Firebase imports were added to UI/domain/features.

WallSpaceRepository serializes writes, checks updatedAt for competing editors, validates records, snapshots/deduplicates source images, and writes metadata after image preparation. Failed writes attempt rollback of every newly created asset. Successful native saves prune unused app-owned image versions only after metadata is durable. Browser metadata owns inline images and quota errors retain prior stored data. File cleanup failures during deletion retain metadata for a retry; partial folder deletion may mean that a room pending deletion cannot be reopened fully. No original-library deletion occurs.

A no-op layout event must retain editor/space identity. A regression test covers this because recreating normalized state for an identical onLayout callback could repeatedly reload/render the SVG. Rendering uses overlapping affine texture triangles with an outer clip to prevent seams. Native and standalone SVG share the same geometry; export uses a denser mesh.

## Features still not implemented

- Native iOS ARKit/LiDAR wall scanning and automatic wall measurements; RoomPlan/3D room reconstruction.
- Sensor-based lighting/white-balance adaptation and automatic depth occlusion. Mild photo-colour suggestions and manual overrides are available.
- Volumetric frame/canvas sides and physically based glazing/materials.
- Vision label OCR/dimension extraction, LiDAR artwork sizing, Find my art photo-library recognition.
- Receiving artwork through OS share-in, perceptual duplicate grouping and large (hundreds of pieces) collection management.
- External artist inventory, artist enquiry delivery, availability/medium/colour/genre metadata and corresponding filters. Current catalogue is the original ArtSpace collection.

An unused speculative native-scanner adapter was removed: a wrapper for a missing native module would not implement scanning. The app does not expose a fake Scan button.

Reference feature inventory: https://apps.apple.com/in/app/placed-art-on-your-walls/id6801124496 . iOS native work needs its own implementation and Mac/device testing; Apple signing is unavailable in this session. Android AR/device installation, native camera capture and OS sharing also need real phone testing. Automated/build success is not hardware acceptance.
